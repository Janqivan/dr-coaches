## PART 6. Workflows and pipelines: node systems, automation, agents and scale

### Rules (ranked by how often they say it)
- **Package it so someone else can run it: lock the rest, expose only inputs and outputs, publish as an app or tool.** App mode shows just the image and prompt in and the 20 images out, with no spaghetti; lock the system-prompt node so nobody edits it; building for app mode is when you really learn to build tools. Co-host Drew Brucker: one builder deploys, the team just runs. [YT:PJ347ccVJBs, YT:N-tmQ_Can_o, YT:EaENLPTAt2E, YT:_az4W2z5Fqw] (n.d.; 2025-12; 2026-09) · mentions 11
- **Skills before agents: one orchestrator plus a roster of skills, not rigid linear chains.** Build the individual skills an agent would need, not the agent; a failure stays inside one skill so you update only that one. He dislikes n8n for this: a linear chain (trigger, step, step) must be rerun whole when a step breaks or an API is off, and fixed pipelines need constant maintenance. [YT:Dl64zUCJniU, YT:92I8aNhyxwM, YT:RNF9xZYHOiQ, YT:1V0xODN21tU] (2026-03 to 2026-09) · mentions 10
- **Put the structure in the system prompt, feed it a loose idea, isolate the one thing that changes.** He no longer writes three- or four-paragraph prompts; one idea becomes 1 prompt or 50. Keep rules generic ("always look at the product"), never brand-specific (no hard-coded "AG1 green"); say shoes, not teal shoes; variables like color get their own node. Well-built workflows need changes about 5% of the time. [YT:PJ347ccVJBs, YT:_az4W2z5Fqw, YT:EaENLPTAt2E, YT:N-tmQ_Can_o] (n.d.; 2025-12; 2026-09) · mentions 9
- **If a process will run more than once, make it a skill, then strip it to generic.** Hard rule; early on he built skills for things he never repeated. "I'm just building a skill for this. I'm not doing this again ever." Then abstract down to minimum viable quality: strip every brand or product detail so it works like "kung fu" for everyone, not just him (same trap as Midjourney personalization). A skill is a full reusable process, not a custom GPT that answers one way; Claude Code skills must be built for Claude Code. (Fast Hours) when a task shows up twice, build a process. [YT:Dl64zUCJniU, YT:N-tmQ_Can_o, YT:RNF9xZYHOiQ, YT:92I8aNhyxwM] (2026-03 to 2026-09) · mentions 9
- **Deconstruct first: ingest, analyze, abstract, rebuild.** Reverse engineer anything (a photo, a business model, a funnel, a landing page, an email) into core components, control each piece, rebuild; he calls the result a "deconstruction agent". Analyze in very small points, abstract by stripping brand and product detail, rebuild generic and file the parts as skills or system prompts. Like a car engine in pieces, a new engine is "that and that and that"; he builds pipelines, then strips them for parts. [YT:6w6pKyCCQFg, YT:AxV8TR3BdqI, YT:_az4W2z5Fqw, YT:1V0xODN21tU] (n.d.; 2026-09) · mentions 7

- **Build evaluation into the system.** Loops iterate until output meets a threshold set by judgment, taste and QA, which prevents slop if you evaluate the right things; build the grade-and-redo loop into the skill. Not "prompt and pray": quality control at every step. [YT:xLLtYn932qY, YT:1V0xODN21tU, YT:_az4W2z5Fqw, YT:nROQ4LJ4GcQ] (n.d.; 2026-08 to 2026-10) · mentions 4

### Methods (named or ordered)
#### Three core skills (any tool, any medium)
- Steps: 1. Deconstruction: reverse engineer a piece of media into core components (teaches how to prompt and write formulas). 2. System prompts: instruct an LLM to do what you did in step 1 and pass info between tools. 3. Workflow development: the sequence of tools from point A to B. Build order: angle, tools, system prompt, workflow.
- Their example: a hamburger into bread, lettuce, tomato, meat, cheese, then reformulate. He keeps the research and trial phase for himself.
- Sources: [YT:PJ347ccVJBs, YT:AxV8TR3BdqI, YT:_az4W2z5Fqw] (n.d.)

#### Begin at the end
- Steps: 1. Get good, provable output by hand (same prompt many times; test the structure 15 ways). 2. Ask how to get that prompt 50 times. 3. Ask what input it needs (reference images, text). 4. Turn your natural prompting into a system-prompt formula that expands a plain idea ("the car is driving down the road"). 5. Build the connective tissue. [quote src: YT:AxV8TR3BdqI]
- Their example: the Meta hook generator mirrors a human team: watch the video and pull hooks, strategist, creative director, copywriter, production.
- Sources: [YT:PJ347ccVJBs, YT:AxV8TR3BdqI, YT:jBcL-XrHqzY] (n.d.)

#### Explore, then systematize
- Steps: 1. Stream-of-consciousness: can I get from A to B with these tools? 2. Once it works, work backwards: which manual prompt becomes an LLM node, which decisions become the system, which branch was only testing. 3. Make the part that changes a variable (apple, banana, coconut) so one word is all anyone types. 4. Second time it comes up, build the skill.
- Sources: [YT:N-tmQ_Can_o] (2026-09)

#### Project versus workflow test
- Steps: 1. If swapping the subject breaks it (teal shoes, one title), it is a project. 2. Make it generic: say shoes, put the variable (color) in its own node, or push the description up into the system prompt so the rest runs automated. Co-host Drew Brucker: swap the shoes at the start and it does about 80% of the work.
- Sources: [YT:EaENLPTAt2E] (2025-12)

#### Batch engine (prompt, LLM, array, list, generators)
- When they use it: one idea needs 3, 10, 50 or 400 outputs; he calls the chain "an engine".
- Steps: 1. Input plus a system prompt that writes N prompts, each ending in a star, asterisk or line break, no commentary. 2. Run Any LLM node (Gemini for speed; Claude sometimes better). 3. Array or line splitter cuts the output into N prompts. 4. List selector (one node per prompt) or text iterator (array and list in one) feeds the generators. 5. Run; raise N by editing "write 10"; a router node carries one input to several nodes.
- Sources: [YT:N-tmQ_Can_o, YT:PJ347ccVJBs, YT:EaENLPTAt2E] (n.d.; 2025-12; 2026-09)

#### Handoff tool
- Steps: 1. Connect output nodes (they signal the workflow's end). 2. Lock nodes you want hidden. 3. Drag inputs where you want them. 4. Create Tool. 5. A teammate types "coconut" and everything runs; Claude sees only published tools (Weave MCP).
- Sources: [YT:N-tmQ_Can_o, YT:PJ347ccVJBs] (2026-09)

#### Orchestrator plus roster
- When they use it: many skills and pipelines exist and he forgets what he owns.
- Steps: 1. Intake skills first (brief intake, asset prep). 2. The orchestrator reads the project and is told to "be resourceful" with what exists. 3. Output goes to review; each run downloads an MD review file (good, go build, or not good). 4. At about 98%, the agent builder files that exact process as a workflow; gaps are reported. 5. An "agent builder constitution" (how he builds agents, how runs flow, what worked) plus reverse-engineer-before-building governs new builds.
- Their example: six Instagram reels, frame extractor, UGC profile, prompt architect, Magnific MCP.
- Sources: [YT:Dl64zUCJniU, YT:1V0xODN21tU, YT:92I8aNhyxwM] (2026-04 to 2026-09)

#### Edge case detector
- When they use it: before the system prompt for a product category ("what else am I not looking for"). [quote src: YT:Dl64zUCJniU]
- Steps: 1. Give it the category. 2. It lists every way inputs can arrive (jewelry: alone on studio, on a person, not visible, in a grid, several products, several in a grid with a person at the bottom). 3. He decides handling for each. 4. Then he builds. Catches roughly 70 to 80 percent.
- Sources: [YT:Dl64zUCJniU] (2026-05)

#### Operational audit: work backwards through the chain
- Steps: 1. Find the killer metric (revisions averaged 3.7 per email, about 2,700 emails of work a month). 2. Trace the cause: not design, copy. 3. Trace the root: copywriters got weak briefs from account managers with 8 to 10 clients and 2 to 4 hours per client per month on the content calendar. 4. Fix: ChatGPT works through the data with them to about 70% of the strategy, then writes "extremely direct, extremely detailed" copy briefs; revisions fell to about 1.7 to 2.1 per email, workload trimmed by a third to two thirds.
- Sources: [YT:E41H2WIHMXg, YT:zPIBzQRJVT8, YT:2H0AluIDW50] (n.d.; 2024-10)

#### Seal team and ghost projects
- Steps: 1. Seal team may use only AI tools (no Photoshop, no Illustrator) to finish projects; forced learning, then they spread it. 2. Ghost projects: seal team and a traditional team take the same brief; track which is faster and better. 3. Show clients labeled AI versus real; clients called the AI work cold and lifeless, then said the same of the traditional work once labels were swapped.
- Sources: [YT:BwFzyeHozFk] (n.d.)

#### Stages of AI adoption and the escalation ladder
- Five stages: 1 find and test tools; 2 daily personal use ("bionic"); 3 everyone differently, no SOPs; 4 SOPs and multi-tool systems; 5 custom-trained models run parts of the business. Most sit at 2 to 3; stage 4 is where this year is heading. Ladder: everyone has a custom GPT, string three together; everyone has a skill, build a pipeline; everyone has a pipeline, build agents.
- Sources: [YT:dcrhhIKNaRQ, YT:zPIBzQRJVT8, YT:xLLtYn932qY] (n.d.; 2024-10; 2026-08)

### Fix library (problem → fix → why)
- **Problem:** clipper picks random viral-sounding lines unrelated to the business → **Fix:** teach it who they are, the target audience, the category hierarchy and the channel mapping → **Why:** more transcripts did not fix it; audience definition did. [YT:nROQ4LJ4GcQ] (2026-10)
- **Problem:** clipper grades hooks wrong because it knows how the story ends → **Fix:** blind grader: read the transcript one word at a time and ask whether the hook was shocking or interesting at first glance, not whether it makes sense in context → **Why:** a stranger scrolling social has no idea what comes next.
